Use this reference when moving a C# Chronicle workflow to Go: find the matching API, its executable evidence and the differences your application must handle. Chronicle.Go uses explicit ownership, contexts and typed registration. The implemented subsets below are **not overall client parity or production lifecycle completeness**.

Start with [baselines and evidence](#baselines-and-evidence), then the relevant capability. Migration guidance covers [connections](#connection-api-and-default-comparison), [constraints](#constraint-api-translation) and [read models](#read-model-migration); [remaining work](#next-slices) separates gaps from delivered APIs.

## Baselines and evidence

C# reference: `Cratis/Chronicle` revision `2e31b0dfba489159b3db323238f16d0f277056b4`, paths below relative to `Source/Clients/`. Generated contracts independently pin Chronicle **19.29.4**, commit `ae5e00a8abaa688138b2c2f689e2b4659cccb4fd`. Real-kernel evidence uses **19.29.4-development**, including test-owned TLS/TCP connection interruption and recovery against a running kernel. Whole-kernel restart and a real multi-node deployment remain unverified. SDK release numbers are independent of protocol versions.

Registration, namespace, serialization and concurrency corrections follow **v19.29.4** at the contract commit above: `Source/Clients/DotNET/Events/EventTypes.cs`, `Source/Clients/DotNET/EventStoreNamespaceName.cs`, `Source/Infrastructure/Schemas/{TypeFormats,JsonSchemaExtensions}.cs`, `Source/Infrastructure/Json/ExpandoObjectConverter.cs`, `Source/Kernel/Storage.MongoDB/ExpandoObjectConverter.cs`, and `Source/Kernel/Core/{EventTypes/EventTypeRegistrar,EventSequences/Concurrency/ConcurrencyValidator}.cs` (repository-root paths).

Statuses: **Implemented** means the named behavior has executable regression evidence; **Partial** names an implemented subset; **Not implemented** claims no usable surface; **Go-specific** identifies an intentional translation. The evidence column names test functions or the actual deterministic generation check, not source reading alone. Status applies to the row's stated contract, not the entire C# feature family.

Read evidence at its actual scope:

- Compiler and source-derived goldens check declarations and wire shape, not execution of the C# client.
- Captured .NET fixtures are identified explicitly with their source and serializer profile; they do not qualify unrelated codecs or generations.
- Go transport tests exercise production SDK paths against controlled replies. Named kernel tests exercise their stated profiles on the pinned server, not every protection route, restart or multi-node deployment.
- Compiling examples and SDK adapter tests do not establish an Arc.Go consumer workflow. Borrowed-facade adoption is tracked separately in [Arc.Go#29](https://github.com/Cratis/Arc.Go/issues/29).
- Native minimum-Go build/unit checks, integration checks and the hosted CI matrix answer different questions. Test references here are not a new run report or a claim that every gate passed on the latest source state.

## JSON wire ordering and escaping

At the Chronicle baseline above, `ChronicleOptions.cs:81` starts with default `JsonSerializerOptions`. `ChronicleClient.cs:360–382` sets naming, null omission and compact output without changing `Encoder`; `Events/EventSerializer.cs` clones those options and calls `SerializeToNode`. Fundamentals `Source/DotNET/Fundamentals/Json/Globals.cs` at `d2accc4a79b6bcf2708213c97093ab5ba6c06381` also leaves `Encoder` unset. `DotNET/Seeding/EventSeeding.cs:128,174` serializes the resulting node using default options.

Go emits struct properties in declaration order, including nested structs, pointers and embedded/promoted fields in `encoding/json` index-path order. The compiled naming policy, explicit tags, nil omission, `omitempty`/`omitzero`, concept codecs and numeric validation still apply. Direct duplicate property names remain configuration errors; ambiguous promoted fields are omitted like `encoding/json`, but declarations on ignored fields fail closed. JSON Schema keeps its existing deterministic key ordering; schema property order does not identify seeded facts.

String values, property names, dictionary keys and string-valued concepts use `JavaScriptEncoder.Default` escaping: non-ASCII characters become uppercase `\uXXXX` escapes (UTF-16 surrogate pairs when needed), as do HTML-sensitive characters, apostrophe, plus, backtick and double quote. Backslash and the standard short control escapes are preserved. `serialization/testdata/csharp-escaped-event.json` and the all-ASCII test were captured from .NET 10 with the options/stages above; the ordered-object and multi-property seed fixtures are hand-derived. This does not implement arbitrary C# custom encoders or `[JsonPropertyOrder]`; equivalent declarations must have the same emitted property order.

**Dictionary limitation:** C# serializes `Dictionary<string, T>` in enumeration order (insertion order for ordinary additions); Go maps retain no insertion history, so their keys remain sorted by Go string order. `TestDictionaryValuesRetainStructDeclarationOrder` and `TestEscapingAppliesToNamesConceptCodecsAndMapKeys` pin deterministic keys without reordering struct values. For byte-sensitive shared seed content, use structs with matching declarations, or arrange the C# dictionary's enumeration to match Go's UTF-8 key order. Arbitrary dictionaries are not byte-parity compatible.

`TestKernelCSharpThenGoSeedsAreIdempotent` sends a C#-derived request followed by the Go request, asserts exact content bytes, and verifies one persisted event. The kernel compares seed content by ordinal string equality (`Source/Kernel/Core/Seeding/EventSeeding.cs:332`), not semantic JSON equality. Previously persisted Go seeds may contain alphabetically ordered properties or different escaping; upgrading does not rewrite that tracking data. Review existing Go seeds before re-registering changed bytes, which the kernel treats as new facts.

## Deliberate differences and migration guidance

1. **TLS validates by default.** C#'s local profile skips validation. Add `WithDevelopmentDefaults` only for development; configure real roots/client certificates with `WithTLS` for production. Explicit validating TLS wins over security opt-outs.
2. **Root registration is explicit and snapshotted.** Use `RegisterEvent[T]`, `RegisterReadModel[T]` and `Registry.AddConstraint` before `NewClient`. Model-bound projection tags and typed type-level options preserve attribute-driven declarations alongside the fluent builder; only root admission replaces assembly scanning. No global `init` registry. `WithRegistryForStore` replaces, rather than merges with, the default catalog.
3. **Context replaces ambient state.** Pass `metadata.WithCorrelation`, `WithIdentity` and `WithCausation`; the client does not invent application/program audit facts. Namespace selection remains explicit and does not grant tenant access.
4. **Errors describe write ambiguity.** Domain rejection is a result; operation failures remain errors. Unknown outcomes are never represented as known rejection. `Err` exposes both constraint and concurrency categories; no transparent append retry is added.
5. **Unsupported options fail.** API keys, plaintext and URI certificate/password formats return `ErrUnsupported`, rather than silently skipping security or routing behavior. Use `WithTLS` for PEM material.
6. **Serialization has a deliberately bounded schema contract.** Fundamentals `Concept[T]` and standard codecs replace `ConceptAs<T>`; plain named primitives remain supported. Explicit JSON tags are recommended. Unsupported custom/protected shapes fail registration; no PII/encryption tag can silently send plaintext. Empty exact type IDs and IDs containing commas fail validation. Scalar/array integers use kernel formats; unsigned values above `MaxInt64` fail before dispatch because the 19.29.4 MongoDB append path parses bare JSON integers as signed BSON integers. Use strings for that range. Dictionary integers outside -2^53 through 2^53 fail before dispatch, including nested values, because the kernel converts dictionary numbers through `double`. Use typed struct properties or strings for wider values. Nullable pointer schemas preserve absence; `omitzero` follows Go `IsZero` methods, but omitted non-nullable fields may materialize as kernel defaults.
7. **Protected concurrency cannot silently downgrade.** No-match uses both wire fields. A confirmed commit without the requested check returns its committed result plus `ErrUnsupported`: do not retry. A single append rejects scopes naming another source; `AppendBatch` supports independently labeled checks. Duplicate labels and source/label mismatches fail locally. Batch check flags mean every scope was checked, so mixed checked/unchecked batches may legitimately report false; the wire carries no per-scope success flags.
8. **Resource ownership is explicit.** Constructors are lazy; `Dial` performs preflight. Close cancels/joins owned work but never closes borrowed channels/token sources. `EventSequence` returns a construction error for invalid IDs rather than publishing an invalid handle. Scalar options are last-wins; conflicting auth modes are errors.
9. **Generation validation matches C# defaults.** Registrations include every concrete schema in `Generations` and default to disabling schema/migration validation, allowing generations above one without migrations. Use `WithEventTypeGenerationValidation(true)` to protect existing generation schemas; `NewClient` then requires the complete adjacent migration chain. Disabled validation permits overwriting history's schema. Shared C#/Go IDs require compatible generated schemas when validation is enabled; identical payload names alone are insufficient.
10. **The default namespace is `Default`.** This corrects the earlier lowercase `default` value to match C# and the kernel. MongoDB rejects namespaces differing only by case; callers must use the kernel spelling or explicitly select another namespace.
11. **Recovery is supervised, not application replay.** Slice 3 replaces slice 1's explicit-connect-after-loss behavior with automatic generation replacement, following `Connections/ChronicleConnection` and `ConnectionWatchdog` at the reference revision above. Old workers join before replacement. Unlike C#'s broad gRPC retry policy and permissive compatibility fallback, Go fails compatibility/authentication closed and never retries an ambiguous append. Terminal failures require an explicit `Connect`; transient reconnect runs with time-bounded attempts and capped jittered backoff until shutdown.
12. **Registration outcomes describe only implemented stages.** Store-wide definitions share a barrier; namespace readiness stays separate. A batch acknowledgement is not a per-artifact verdict. Transient registration failures receive bounded retries and delayed background retry; deterministic validation/authorization failures require an explicit retry rather than endlessly repeating. Go adds a per-attempt budget and a 64-endpoint discovery/probe bound. For [runtime projection additions](#runtime-projection-additions), `Published` records retained local admission separately from stage acknowledgements; other artifact families and replacement remain unsupported.
13. **Shutdown is context-bounded without breaking `Close()`.** `Shutdown(ctx)` drains admitted RPCs, then cancels and joins; `CloseContext(ctx)` immediately cancels and bounds the join. A timeout reports incomplete cleanup, which continues until cooperative callbacks return. The unchanged `Close() error` remains an unbounded cancellation/join convenience. Borrowed channels retain caller ownership.
14. **Read filters describe kernel history, not exact routes.** Empty/default sentinel dimensions do not narrow. Event types match IDs across generations; normalized history filters sort/deduplicate IDs and use generation one. Raw JSON plus generation metadata replaces automatic CLR deserialization. Read results are ordered and malformed/duplicate positions fail; these finite queries do not imply a multi-query snapshot or revision/redaction protection.
15. **Batch scope enrollment is explicit.** A unique label matching a source replaces that source's default first-entry-route scope. Independent labels need no corresponding event. Like C# `EventsWithConcurrencyScopes`, duplicate labels fail, including identical duplicates. Unlike that C# wrapper's restriction on unresolved independent scopes, Go can explicitly `Resolve` an independent filter before the atomic append. An unchecked empty batch is rejected locally. Eventless protected checks work with 19.29.4; an older kernel's event-required validation becomes `ErrUnsupported`, not a no-op success.
16. **Persisted timestamp precision is kernel-limited.** The Go wire keeps 100 ns precision, but the 19.29.4-development MongoDB kernel returns occurrence/causation dates truncated to milliseconds. `TestKernelOrderedAtomicBatchAndHistory` records this server behavior; `TestReadPreservesEnvelopeMetadataAndGenerations` proves conversion retains all precision actually returned. No client-side reconstruction or extra persistence path is invented.

Batch/read C# references above use revision `2e31b0dfba489159b3db323238f16d0f277056b4`; kernel behavior is exercised against the pinned 19.29.4-development image. The runnable [batch example](../examples/batches/main.go) also uses the public production APIs.

## Append configuration and declaration migration

Register the subject policy once alongside the event schema:

```go
registered, err := chronicle.RegisterEvent[CustomerChanged](registry,
    events.WithSubjectResolver(func(event CustomerChanged) (events.Subject, bool) {
        return events.Subject(event.CustomerID), event.CustomerID != ""
    }))
```

`CustomerChanged` is the application's named event struct; the callback must match
that exact declaration type. An append-level `WithSubject` (or `Entry.Subject`)
wins without invoking the callback. Missing subjects fall back to the source ID.

Add `chronicle.WithCheckFirstAppendIntoAScope(true)` to client construction to
protect first writes across all sequence handles, batches and unit-of-work commits.
It stays off by default, matching C# `ConcurrencyOptions`. Explicit `NoCheck`
remains unchecked. A competing writer after an empty-tail read becomes a known
concurrency rejection rather than an unchecked success.

`WithDefaultConcurrencyStrategy` preserves C#'s extension point without dependency
injection: the callback receives the sequence and default source/route filter.
Return an explicit expectation after a `sequence.Tail(ctx, eventsequences.TailFilter(filter))` read, or return
`Resolve` to have the SDK perform its existing matching-tail read. Explicit
expectations do not trigger an extra read. Batch defaults invoke the strategy once
per source using its first entry's route; units of work defer it to commit, never
staging. No retry or extra kernel round-trip is required by this translation.

Call `sequence.ResolveScope(ctx, filter)` to apply this same policy to selected
concurrency dimensions before staging. Resolve each target independently, then
label the returned scopes for `Stage`/`AppendBatch`. This adds no route defaults.
Resolved scopes never reread their tails at dispatch, even when an empty tail is
unchecked under the default first-append policy; that unchecked result retains
its filter but is distinct from an unresolved `Resolve` expectation.

Operation metadata is available through the new `*WithMetadata` append methods,
not by changing the original public result structs. `Operation().EventTypes()`
retains generations on success, rejection and unknown outcomes; `Result().Target`
still describes only confirmed committed work. Local failures include registered
input types only, because an unregistered value has no persisted identity. Existing
callers can keep their original methods and unkeyed literals unchanged.

Message bounds cover serialized protobuf messages, not just event JSON. Small
limits can therefore reject compatibility, the mandatory authenticated readiness
probe, registration or observer requests as well as appends and reads. Both `Invoke` and `NewStream` apply explicit settings
on the shared generation transport; no borrowed channel is mutated or closed.
An explicit value equal to the SDK default still overrides a borrowed owner's
limit. Omitted settings preserve that owner's limits.

Compatibility preflight remains fail-closed unless explicitly skipped. It is
anonymous on the kernel and cannot prove authenticated readiness. With a skipped
application session, startup always calls protected, read-only
`GetConnectedClients`, even when compatibility is disabled. Authentication,
authorization and unsupported-method failures are surfaced without fabricating
connection registration or retrying the rejected operation. The
**19.29.4-development** witness verifies anonymous rejection and authenticated
registration/append/read. It checks for new Go session IDs belonging to its own
process, not an empty or unchanged global client list: other fixture processes
can have active sessions and changing heartbeat timestamps. The public SDK does
not expose a skipped client's internal connection ID; the serial process-local
check is narrower than proof by individual client ID. The transport unit tests
also verify that skipping keepalive dispatches no `Connect` RPC.

The kernel test pins the compatibility request's exact protobuf send boundary
(126854 bytes), with a separate 64 KiB bounded startup receive envelope. A
128 KiB event in a unique immutable source then supplies the target event-read
receive boundary, measured from grpc-go's uncompressed incoming payload length.
Both equality and one-byte-short are asserted through owned public SDK clients,
including successful startup and registration before the target read; oversize
reads return no partial history. The fixture cap is 512 KiB. Re-serializing a
Go-decoded response with `proto.Size` is not an exact wire-size witness because
the kernel's protobuf-net serializer emits explicit defaults that Go omits.
The small compatibility response is not used as a client-wide receive cap:
`GetConnectedClients` can legitimately return a larger shared-session envelope.
Exact unary and streaming transport bounds remain covered by bufconn tests.

A skipped session has no application heartbeat-driven logical reconnect or
registration replay guarantee after a kernel restart. grpc-go transport
reconnection is not a replacement for that lifecycle. Startup/replacement
registration workers still belong to their generation; cancellation, `Close`,
`CloseContext` and `Shutdown` join client-owned work as usual. Prefer skipped
sessions for short-lived one-shot clients. TLS verification, credential ownership
and the no-append-retry contract are unchanged; no idle-ping guarantee is added.

## Unit-of-work migration

Transaction references use C# revision `2e31b0dfba489159b3db323238f16d0f277056b4`, `Source/Clients/DotNET/Transactions/{IUnitOfWork,IUnitOfWorkManager,UnitOfWork,UnitOfWorkManager,UnitOfWorkLifecyclePolicy}.cs`. The Arc consumer reference is `Source/DotNET/Chronicle/Commands/TransactionalCommandScope.cs`: completion is distinct from confirmed commitment, and early commitment completes shared work.

1. **Separate participant and owner.** Replace ambient `IUnitOfWorkManager.Begin/Current/SetCurrent/TryGetFor` with `transactions.Begin` and explicit participant context accessors. Go has no `AsyncLocal`; there is no global correlation registry. `UnitOfWork.Stage` translates `AddEvents`. Only the separately retained `Owner` exposes `Commit`/`Rollback`; this capability split also keeps ordinary Arc handlers from completing outer work. The store, namespace, sequence, correlation and actor are fixed at begin. Missing correlation is generated once; actor changes fail because one atomic request cannot represent several actors.
2. **Strict lifecycle and global order.** Go uses C#'s strict-policy intent, not its legacy compatibility mode. All enrollment retains A1/B1/A2 order instead of legacy single-event source grouping. Events serialize at `Stage`, not commit, so later mutations cannot change the transaction. Concurrent stage calls enroll atomically; no serialization callback or RPC runs under the state lock. Repeated equal explicit scopes join, while conflicting scopes fail without mutation. An explicit `Resolve` is not C#'s absent `NotSet`: it includes a filter and cannot overwrite an enrolled expectation. Use omission for the default strategy.
3. **Inspect final disposition, not completion alone.** `Commit` returns the existing Go `BatchResult` and operation error; `Result`, C#-named diagnostic getters, `IsSuccess` and `TryGetLastCommittedEventSequenceNumber` preserve the query workflow. `GetEvents` returns defensive JSON snapshots rather than mutable CLR event objects. Transport loss and errors-only kernel results remain outcome-unknown, not a successful default result or known rejection. All attempts are terminal, including local cancellation; retry requires a deliberate new unit and fresh decision, and is never safe merely because an ambiguous owner completed. The retained result survives a repeated commit error. Empty completion is successful without persistence; scope-only completion still validates through the kernel.
4. **Explicit rollback instead of disposal.** Defer `Owner.Rollback` for pending cleanup. Unlike C#'s repeated rollback exceptions, terminal rollback is a no-op so ordinary Go defer does not mask a successful result; it never changes a committed or ambiguous disposition. During completion it fails with `ErrCompleting`. Rollback reports `RolledBack` and is not `IsSuccess`, avoiding C#'s success-shaped empty append result being mistaken for commitment.
5. **Completion notification retains the C# name and replacement semantics.** `OnCompleted` replaces the callback and runs synchronously after final state, including commit failure and rollback. Go rejects late registration with `ErrCompleted` rather than silently retaining an uncallable callback. No manager-cleanup callback is replaceable, since lifetime belongs to the explicit owner. Callback panic propagates after final disposition is recorded.

The [unit-of-work guide](events/unit-of-work.md) and [executable example](../examples/unitofwork/main.go) show the participant/owner workflow. Prepared batches are a lower-level serialization seam, not another owner: they do not provide once-only completion. [Admitted decision reads](read-models/decision-reads.md) supply opaque optimistic tokens; ordinary concurrency scopes must not be presented as decision tokens.

- **Choose model-bound declarations or explicit definitions.** Field `unique` tags, `events.WithUnique` and remover options compile through the same builders as `UniqueValues(name).On(descriptor, paths...)`. Use one grouped definition instead of C#'s same-name declaration merging; duplicate names across `AddConstraint` calls are rejected atomically. Repeated covered/removal IDs and selected sequences coalesce in first-declaration order. Scope calls apply to the one definition regardless of call order, avoiding C#'s multi-definition builder's order-sensitive scope capture.
- **Messages remain client-side.** Missing/empty templates preserve the kernel text, and callbacks run once per matching returned violation as in C# append conversion. Providers run outside the RPC lease so they can use client lifecycle APIs without self-deadlocking; shutdown does not wait for caller-owned message formatting.

Outcomes include the `constraints` stage; the RPC returns `google.protobuf.Empty`, not a command envelope. Empty local constraint sets perform no RPC, matching the Go event-registration fast path; no API for deleting persistent definitions is implied. Store-specific registries replace both events and constraints. Adding constraints after client construction still requires a new client; [runtime projection additions](#runtime-projection-additions) do not add constraints.

No UUID dependency, new scalar type, local uniqueness algorithm or preflight read is added. Low-level `eventsequences.New` has no registry/message provider and preserves kernel text; obtain sequences from `EventStore` for registered message resolution. Claim removal and batch ordering are server behavior, not emulated by a Go test fake.

## Read-model migration

Read-model references use the C# baseline revision above, `Source/Clients/DotNET/ReadModels/{IReadModels,ReadModels,ReadModelTypeExtensions,ReadModelJsonSerialization,ReadModelReleaser,ReadModelSubjectResolver}.cs` and `Source/Kernel/Grpc/ReadModels/ReadModels.cs`. Container naming follows the `Cratis.Serialization.DefaultNamingPolicy` used by `ChronicleClient`: a case-preserving Humanizer plural of the simple type name. The vocabulary adaptation and MIT attribution are pinned in `readmodels/HUMANIZER-LICENSE`.

1. **Explicit declarations replace discovery.** `RegisterReadModel[T]` supplies the schema and producer association separately from projection/reducer registration. A registered model can be read without a locally known handler, unlike C#'s handler-existence guard; this supports catalog consumers such as Arc.Go without fabricating a producer. Registrations use generation one, MongoDB, an empty configuration UUID, `Client` owner, `Code` source and projection observer type by default. Model definitions join the registration pass immediately after event types and replay once per store/generation, with per-namespace read barriers. Passive (`NoSink`) models require a nonblank producer identifier; `readmodels.Passive()` defers that binding to a registered reducer (`TestReducerPassiveAndInactiveBinding`). Materialized models may omit the producer. Repeated `WithIndexes` and `WithPII` calls accumulate copied property paths in declaration order and reject duplicates within or across calls with `ErrInvalidConfiguration`. [Runtime projection additions](#runtime-projection-additions) admit a new ordinary model together with its new projection; no standalone runtime `RegisterReadModel[T]` or replacement API is provided.
2. **Identity and container names stay distinct.** C# uses `Type.FullName`; Go uses its import-qualified type name, not the simple event-type naming convention. For shared persisted models, use `WithIdentifier("CSharp.Namespace.Model")`. `WithContainerName` corresponds to C#'s `ReadModelNameAttribute`, not a model identifier override. Generic Go instantiations require both `WithIdentifier` and `WithContainerName` explicitly: reflection's argument-qualified type names are not stable persisted identities or valid conventional container names. `TestGenericReadModelRequiresExplicitNames` covers rejection and explicit registration. The shared serialization plan preserves property names by default, matching C# `DefaultNamingPolicy`; camelCase is opt-in, and explicit JSON tags take priority. An untagged root Go `ID` becomes C# `Id`; nested fields and other initialisms retain their policy names. `TestNamingPoliciesCompileOneFieldPlan` and `TestReadModelPlanTranslatesOnlyUntaggedRootID` cover these rules. Keep persisted names stable with explicit tags or a deliberate naming policy; changing policy is a schema migration, not a cosmetic rename. The golden registration request derives envelope/defaults from C# while using the Go plan's equivalent JSON Schema, not a claim of byte-identical NJsonSchema output.
3. **Presence and progress are separate.** `Instance[T].Exists` replaces a nullable model; `LastHandled` replaces C#'s injected `__lastHandledEventSequenceNumber` property. A missing model never becomes a present zero value. Raw documents retain their metadata. Slice fields in present models normalize missing/null collections to empty; pointer-to-slice fields preserve nullable absence and maps are not normalized. The one-shot API rejects the kernel's `*` replay wildcard rather than treating it as an ordinary key. Raw/typed `GetAll`, materialized paging, watches and admitted projection snapshots are available. Their count, presence and replay rules differ: use the [collection/history reference](read-models/collections-and-history.md) and [watch reference](read-models/index.md#watch-changes). Reducer snapshots and classified projection replay/history remain unsupported.
4. **Sessions have explicit cleanup contexts.** `NewSession` creates an opaque random ID, binds all coordinates and performs no I/O until Get. `Close(ctx)` dehydrates, reports errors and permits cleanup retry after failure; it is intentionally not `io.Closer`, so callers retain cancellation/deadline ownership. Unlike C#'s unconditional event-log dehydration, Go sends the session's actual sequence. Close sessions before the client. No cross-reconnect hydration continuity or decision-token guarantee is claimed. Reducer sessions remain unsupported, but passive reducer Get and explicitly bounded collection folds run locally through the registered fold plan. Classified projection sessions and immediate reads refuse before RPC (`TestProtectedProjectionRoutesRefuseBeforeRPCRegardlessOfIdentityAndClassification`); ordinary session coordinate/cleanup behavior is covered by `TestReadModelSessionRetainsCoordinatesAndRetriesFailedCleanup`.
5. **Release fails closed.** C# returns unchanged values for missing subjects or reported release failure. Go returns `ErrRelease` with no value, preserves underlying error identities and redacts public error text. Release ownership is route-specific: materialized keyed/collection results and store-owned passive folds validate already-released data without another decrypt; classified projection replay/history/immediate/session/decision reads refuse before RPC. Admitted MongoDB root-string PII/EncryptedNamespace windows validate server-released data without Release; classified sink identity aliases and other protection profiles refuse before RPC (see the [window profile](read-models/index.md#materialized-windows)). Classified projection Watch refuses before streaming ([Chronicle#4566](https://github.com/Cratis/Chronicle/issues/4566)); classified local reducer Watch refuses before queue attachment without a delivery-time erasure fence. Unclassified local notifications validate final plaintext without Release. Repeated Release is not a safety check. Explicit release accepts unreleased documents only, never already-released plaintext: raw documents preserve subject lineage, with stored `__subject` taking precedence over a configured property and the Go `ID` fallback. Strings and JSON numbers resolve subjects; numeric token text is preserved without floating-point conversion. Null, empty strings, objects and arrays do not resolve a subject. As in kernel `ReadModelsCompliance.HandleBySubject`, top-level properties are grouped by their `__subjects` entry, falling back to the resolved default subject. Each group is released under its own subject and the replies are merged; any group failure returns no document. Typed release uses the same path after serialization and requires the subject on the value. This intentionally adds raw-document lineage handling absent from the typed C# helper. PII and distinct confidentiality classifications share this pipeline. Namespace/global-only values need no subject; present subject-dependent values still fail without ownership. Cryptographic/erasure semantics remain kernel-owned, not a client-side cipher heuristic.

The [read-model reference](read-models/index.md), `ExampleRegisterReadModel` and [runnable example](../examples/readmodels/main.go) use these public APIs. Kernel registration, absence, producer-backed materialization and passive reads are tested on 19.29.4-development. Session hydration/dehydration and explicit release failures retain bufconn evidence, not a claim of complete projection/compliance integration.

### Shared reducer recovery defect

Go preserves C#'s failed-batch response: last successful observation with no state.
At Chronicle revision `2e31b0dfba489159b3db323238f16d0f277056b4`,
`Source/Kernel/Core/Observation/Reducers/ReducerPipeline.cs:59–75` reloads the
sink state and writes nothing on failure. `Observer.Handling.cs:166–205` advances
observation progress and records a live failure at the last successful event.
`Observer.Failing.cs:223–229` and `Jobs/RetryFailedPartition.cs:89–104` restart
recovery there, inclusively (`Storage.MongoDB/EventSequences/EventSequenceStorage.cs:920–926`).
They do not rebuild from the beginning of the failed batch or event history.
Consequently, successful prefix folds before that restart position are lost.
A failed recovery step additionally checkpoints success and records its next
failed event (`Jobs/HandleEventsForPartition.cs:182–190,236–272`), again without
persisting the prefix. This upstream defect is tracked in
[Chronicle #4540](https://github.com/Cratis/Chronicle/issues/4540); Go does not
change the failure wire contract independently. This conclusion is based on
source inspection, not a live-kernel recovery test.

## Next slices

Delivered event declarations, historical catalogs, operations, bounded folds and
facade helpers are not future slices. The remaining porting work is:

- **Safety:** [#48](https://github.com/Cratis/Chronicle.Go/issues/48) now reproduces missing webhook authorization schemas in fresh non-System stores for SDK and C#-source-equivalent requests; [Chronicle#4567](https://github.com/Cratis/Chronicle/issues/4567) tracks kernel registration scope and ignored append failures. The guarded regression remains blocked there; an actual .NET request capture and other historical intermittent triggers are not established. [#18](https://github.com/Cratis/Chronicle.Go/issues/18) sequence sentinels, predicates and checked pure arithmetic are implemented in the sequence-number row above, not future work.
- **Read and protection routes:** [#33](https://github.com/Cratis/Chronicle.Go/issues/33) / [#35](https://github.com/Cratis/Chronicle.Go/issues/35) remaining unsupported window profiles, classified projection Watch blocked by [Chronicle#4566](https://github.com/Cratis/Chronicle/issues/4566), classified local-watch delivery-time erasure fencing, reducer snapshots and protected forwarding/erasure. Existing classified projection replay/history/immediate/session and decision refusals remain; global confidentiality and protected forwarding/erasure are unverified. Count-zero success is not protected-read evidence.
- **Model-bound and representation depth:** [#26](https://github.com/Cratis/Chronicle.Go/issues/26) other complex context mappings and clear representations beyond direct compiled nullable slice/string-keyed map pointers; [#27](https://github.com/Cratis/Chronicle.Go/issues/27) derived-child lowering, blocked by Chronicle#4564; [#64](https://github.com/Cratis/Chronicle.Go/issues/64) enum/flags schema and configured serializer profiles, binary/custom representations, complex/concept map keys and GeoJSON. Closed unprotected families do not imply protected polymorphism or safe direct family-valued derivative properties.
- **Runtime ownership:** [#62](https://github.com/Cratis/Chronicle.Go/issues/62) store eviction, lifecycle hooks and custom balancing; [#63](https://github.com/Cratis/Chronicle.Go/issues/63) runtime registration of other artifact families and replacement profiles. Bounded [runtime projection additions](#runtime-projection-additions) and coherent store publication are implemented. Private immutable startup preparation remains a prerequisite (`TestPreparedOutputCompositionNeverRepeatsApplicationPreparation`, `TestFailedPreparationNeverRetainsPartialOutputs`), not a separate authoring framework. Registration sends still do not prove observer attachment.
- **Outgoing conventions:** [#65](https://github.com/Cratis/Chronicle.Go/issues/65) ordered enrichment, actor/correlation/root-causation providers and high-level identity rename. Explicit metadata is not provider-discovery parity.
- **Scenarios and declaration tooling:** [#38](https://github.com/Cratis/Chronicle.Go/issues/38) initial-state/strict-subscription fidelity and lifecycle conformance; [#23](https://github.com/Cratis/Chronicle.Go/issues/23) generation and [#39](https://github.com/Cratis/Chronicle.Go/issues/39) declaration analysis. The [module policy](module-policy.md) is delivered; generators/analyzers are not. Manual/runtime/generated equivalence and body-sensitive reducer versions still need executable witnesses.

Cross-client naming and two-generation evolution evidence, independent Arc.Go
consumer adoption, whole-kernel restart and multi-node behavior remain distinct
from the implemented SDK contracts. Keep upstream restrictions until the exact
failing profile has a passing witness; no optional adapter experiment substitutes
for this remaining parity work.
