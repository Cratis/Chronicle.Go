Chronicle.Go targets the C# client's concepts and behavior, expressed through Go's explicit ownership, contexts and typed registration. This foundation is **not overall client parity or production lifecycle completeness**.

## Baselines and evidence

Generated contracts independently pin Chronicle **19.29.4**, commit `ae5e00a8abaa688138b2c2f689e2b4659cccb4fd`. Real-kernel evidence uses **19.29.4-development**, including test-owned TLS/TCP connection interruption and recovery against a running kernel. Whole-kernel restart and a real multi-node deployment remain unverified. SDK release numbers are independent of protocol versions.

## Deliberate differences and migration guidance

1. **TLS validates by default.** C#'s local profile skips validation. Add `WithDevelopmentDefaults` only for development; configure real roots/client certificates with `WithTLS` for production. Explicit validating TLS wins over security opt-outs.
2. **Registration is explicit and snapshotted.** Replace attributes/assembly scanning with `RegisterEvent[T]` and `Registry.AddConstraint` before `NewClient`. No global `init` registry. `WithRegistryForStore` replaces, rather than merges with, the default catalog.
3. **Context replaces ambient state.** Pass `metadata.WithCorrelation`, `WithIdentity` and `WithCausation`; the client does not invent application/program audit facts. Namespace selection remains explicit and does not grant tenant access.
4. **Errors describe write ambiguity.** Domain rejection is a result; operation failures remain errors. Unknown outcomes are never represented as known rejection. `Err` exposes both constraint and concurrency categories; no transparent append retry is added.
5. **Unsupported options fail.** API keys, plaintext and URI certificate/password formats return `ErrUnsupported`, rather than silently skipping security or routing behavior. Use `WithTLS` for PEM material.
6. **Serialization has a deliberately bounded schema contract.** Named primitives replace `ConceptAs<T>`. Explicit JSON tags are recommended. Unsupported custom/protected shapes fail registration; no PII/encryption tag can silently send plaintext. Empty exact type IDs and IDs containing commas fail validation. Scalar/array integers use kernel formats; unsigned values above `MaxInt64` fail before dispatch because the 19.29.4 MongoDB append path parses bare JSON integers as signed BSON integers. Use strings for that range. Dictionary integers outside -2^53 through 2^53 fail before dispatch, including nested values, because the kernel converts dictionary numbers through `double`. Use typed struct properties or strings for wider values. Nullable pointer schemas preserve absence; `omitzero` follows Go `IsZero` methods, but omitted non-nullable fields may materialize as kernel defaults.
7. **Protected concurrency cannot silently downgrade.** No-match uses both wire fields. A confirmed commit without the requested check returns its committed result plus `ErrUnsupported`: do not retry. A single append rejects scopes naming another source; `AppendBatch` supports independently labeled checks. Duplicate labels and source/label mismatches fail locally. Batch check flags mean every scope was checked, so mixed checked/unchecked batches may legitimately report false; the wire carries no per-scope success flags.
8. **Resource ownership is explicit.** Constructors are lazy; `Dial` performs preflight. Close cancels/joins owned work but never closes borrowed channels/token sources. `EventSequence` returns a construction error for invalid IDs rather than publishing an invalid handle. Scalar options are last-wins; conflicting auth modes are errors.
9. **Generation validation matches C# defaults.** Registrations include the current schema in `Generations` and default to disabling schema/migration validation, allowing generations above one without migrations. Use `WithEventTypeGenerationValidation(true)` to protect existing generation schemas; generations above one then require migration authoring, which is not implemented. Disabled validation permits overwriting history's schema. Shared C#/Go IDs require compatible generated schemas when validation is enabled; identical payload names alone are insufficient.
10. **The default namespace is `Default`.** This corrects the earlier lowercase `default` value to match C# and the kernel. MongoDB rejects namespaces differing only by case; callers must use the kernel spelling or explicitly select another namespace.
11. **Recovery is supervised, not application replay.** Slice 3 replaces slice 1's explicit-connect-after-loss behavior with automatic generation replacement, following `Connections/ChronicleConnection` and `ConnectionWatchdog` at the reference revision above. Old workers join before replacement. Unlike C#'s broad gRPC retry policy and permissive compatibility fallback, Go fails compatibility/authentication closed and never retries an ambiguous append. Terminal failures require an explicit `Connect`; transient reconnect runs with time-bounded attempts and capped jittered backoff until shutdown.
12. **Registration outcomes describe only implemented stages.** Store-wide definitions share a barrier; namespace readiness stays separate. A batch acknowledgement is not a per-artifact verdict. Transient registration failures receive bounded retries and delayed background retry; deterministic validation/authorization failures require an explicit retry rather than endlessly repeating. Go adds a per-attempt budget and a 64-endpoint discovery/probe bound. Runtime registry extension remains deferred.
13. **Shutdown is context-bounded without breaking `Close()`.** `Shutdown(ctx)` drains admitted RPCs, then cancels and joins; `CloseContext(ctx)` immediately cancels and bounds the join. A timeout reports incomplete cleanup, which continues until cooperative callbacks return. The unchanged `Close() error` remains an unbounded cancellation/join convenience. Borrowed channels retain caller ownership.
14. **Read filters describe kernel history, not exact routes.** Empty/default sentinel dimensions do not narrow. Event types match IDs across generations; normalized history filters sort/deduplicate IDs and use generation one. Raw JSON plus generation metadata replaces automatic CLR deserialization. Read results are ordered and malformed/duplicate positions fail; these finite queries do not imply a multi-query snapshot or revision/redaction protection.
15. **Batch scope enrollment is explicit.** A unique label matching a source replaces that source's default first-entry-route scope. Independent labels need no corresponding event. Like C# `EventsWithConcurrencyScopes`, duplicate labels fail, including identical duplicates. Unlike that C# wrapper's restriction on unresolved independent scopes, Go can explicitly `Resolve` an independent filter before the atomic append. An unchecked empty batch is rejected locally. Eventless protected checks work with 19.29.4; an older kernel's event-required validation becomes `ErrUnsupported`, not a no-op success.
16. **Persisted timestamp precision is kernel-limited.** The Go wire keeps 100 ns precision, but the 19.29.4-development MongoDB kernel returns occurrence/causation dates truncated to milliseconds. `TestKernelOrderedAtomicBatchAndHistory` records this server behavior; `TestReadPreservesEnvelopeMetadataAndGenerations` proves conversion retains all precision actually returned. No client-side reconstruction or extra persistence path is invented.

Batch/read C# references above use revision `2e31b0dfba489159b3db323238f16d0f277056b4`; kernel behavior is exercised against the pinned 19.29.4-development image. The runnable [batch example](../examples/batches/main.go) also uses the public production APIs.

## Connection API and default comparison

This slice compares `DotNET/ChronicleClient.cs`, `ChronicleOptions.cs`, `EventStore.cs`, `Registrations/{RegistrationRetryOptions,RegistrationBackoff,SingleFlightRegistration}.cs`, and the connection sources in the table above at revision `2e31b0dfba489159b3db323238f16d0f277056b4`. Go spellings avoid package stuttering and `Get` prefixes; the underlying concepts remain client, event store, namespace, connection and registration.

| Concern | C# counterpart/default | Go behavior and deliberate difference |
| --- | --- | --- |
| Client construction and stores | `ChronicleClient`, `GetEventStore`, `GetEventStores` | `NewClient`/`Dial`, `EventStore`, `EventStores`; explicit contexts and construction errors, frozen options rather than mutable `Options` |
| Endpoint/authentication | `localhost:35000`, development client credentials | Same endpoint and credentials; validated TLS is the safety difference described above |
| Connection budget | `ConnectTimeout = 5` seconds; initial-startup and post-failure wait behavior differ | `WithConnectTimeout`, five seconds for each complete discovery/auth/handshake attempt; first attempt returns its actual failure rather than reporting an unready connection as connected. Subsequent readiness waits use the caller's deadline |
| Heartbeats and transport pings | Fixed five-second staleness, evaluated on a one-second watchdog tick; HTTP/2 60s/30s | Same default thresholds/pings; timer-driven staleness is configurable with `WithKeepAliveTimeout`, without the extra polling tick |
| Reconnect | Watchdog retries with exponential 1–30s delays, lifecycle disconnect/connect notifications | Same automatic replacement and re-registration; Go adds half-to-full downward jitter to avoid synchronized fleets, joins old workers, and stops on terminal authentication/compatibility errors |
| Calls during recovery | Service accessor attempts connection, subject to failure backoff | Existing handles fail before dispatch while disconnected, rather than making every RPC wait for reconnection. Use `Ready(ctx)` when waiting is appropriate; replay barriers block required operations |
| Balancing | Factory defaults to least-connections despite a stale round-robin options comment; random-offset round-robin/random alternatives | Same algorithms and URI names; at most 64 endpoints, no custom balancer extension yet. A borrowed channel retains its owner's routing |
| OAuth | 60s refresh margin, 5s failure throttle, 3600s fallback lifetime, forced refresh on rejection | Same cache/refresh constants; five-second HTTP request cap and a fresh endpoint-bound OAuth cache per generation. This intentionally avoids carrying a token across server restarts; no automatic unary replay |
| Registration within a pass | Five attempts; initial 2s/max 30s half-to-full jitter, retries the full artifact pass | Same attempt count and delay defaults; 30s per-attempt cap. Only transient failures retry automatically; acknowledged store-level stages are shared rather than resent per namespace |
| Registration between passes | Per-store background exponential 2–30s delay plus single-flight failed-pass backoff (1–60s) | One generation-owned worker scans pending registrations at `MaximumDelay` (30s default), reducing background fan-out. An explicit subsequent wait may start a fresh pass immediately; it does not add C#'s second backoff layer. Applications must not hot-loop explicit waits; use the owned background retry or a caller deadline |
| Readiness and outcomes | `Registration`, `WaitForRegistration`, `RegisterAll`, `Lifecycle.IsConnected` | `WaitForRegistration(ctx)` returns a generation/pass outcome; `Ready(ctx)` separates connection health from artifact readiness. Only implemented store/namespace/event-type/constraint stages are represented; runtime `RegisterAll`/registry extension is deferred |
| Failed store creation | Evicts a failed lazy task from the name/namespace cache | Retains the immutable handle but never caches failure as successful readiness; later passes and reconnect can recover it. No failed task permanently poisons admission |
| Disposal | `Dispose()` cancels owned connection lifetime and disposes the supplied connection | `Close()` cancels/joins only owned resources; `CloseContext` bounds joining and `Shutdown` adds deadline-bounded RPC draining. Borrowed channels are never disposed |
| Remaining option/lifecycle surface | `SkipKeepAlive`, configurable message limits, `EvictEventStores`, lifecycle event hooks, process/software metadata and custom balancer | Not implemented in this slice. Keep-alive remains mandatory, message limits remain 100 MiB each (matching C# defaults), handles persist until client close, and no public connection-event callbacks are exposed. These are explicit gaps, not ignored options |

## Constraint API translation

Constraint references use `DotNET/Events/Constraints` and its matching `DotNET.Specs/Events/Constraints` at the baseline revision above. Request fixtures derive from `ConstraintBuilder`, `UniqueConstraintBuilder`, `ConstraintConverters`, and the converter/sequence/remover specs, rather than from a Go-generated expectation. Kernel behavior is exercised against 19.29.4-development. The [constraint example](../examples/constraints/main.go) uses the same production registry and append APIs.

- **Explicit definitions replace attributes and `IConstraint.Define`.** `UniqueValues(name).On(descriptor, paths...)` requires a stable name because Go has no constraint-owner CLR class whose name can be inferred. Paths are exact serialized JSON names, validated against the descriptor schema; use `Descriptor()` from `RegisterEvent[T]`. No expression inspection, property-name inference, field-tag scanning or attribute-provider merging is performed. Empty property sets, blank names/sequence IDs and foreign descriptors fail early rather than allowing inert or ambiguous declarations. `TestMalformedConstraintDefinitionsFailBeforeRegistration` and `TestConstraintRegistryRejectsInvalidOrForeignDeclarations` cover admission.
- **Existing kind constants stay compatible.** `constraints.Unique` and `constraints.UniqueEventType` remain result-kind constants; builders are named `UniqueValues` and `UniqueEventTypes` to avoid breaking those exported names. The event-type builder defaults to the first persisted event ID, matching C# `Unique<T>()`, and accepts multiple types for mutual exclusion. Use one grouped definition instead of C#'s same-name declaration merging; duplicate names across `AddConstraint` calls are rejected atomically. Repeated covered/removal IDs and selected sequences coalesce in first-declaration order. Scope calls apply to the one definition regardless of call order, avoiding C#'s multi-definition builder's order-sensitive scope capture.
- **Messages remain client-side.** Missing/empty templates preserve the kernel text, and callbacks run once per matching returned violation as in C# append conversion. Go supplies copied details to callbacks and inserts values literally in one pass; unlike C#'s sequential dictionary replacement, values containing `{OtherDetail}` cannot become a second template expansion. This removes map-iteration-order dependence and avoids interpreting event values as formatting instructions. `TestMessageDetailValuesAreLiteral` fixes that deliberate edge-case difference. Use a provider for intentional complex formatting; synchronize captured mutable state. Providers run outside the RPC lease so they can use client lifecycle APIs without self-deadlocking; shutdown does not wait for caller-owned message formatting.
- **Registration acknowledges a batch, not each name.** Constraints use the same generation-scoped store barrier as event types, after event registration and before future observer stages. Outcomes include the `constraints` stage; the RPC returns `google.protobuf.Empty`, not a command envelope. Empty local constraint sets perform no RPC, matching the Go event-registration fast path; no API for deleting persistent definitions is implied. Store-specific registries replace both events and constraints. Adding constraints after client construction requires a new client until runtime extensions exist.
- **Results remain additive and kernel-owned.** Append/AppendMany/AppendBatch retain their existing violation/result/error types, now resolving registered messages and exposing standard detail-key constants. No UUID dependency, new scalar type, local uniqueness algorithm or preflight read is added. Low-level `eventsequences.New` has no registry/message provider and preserves kernel text; obtain sequences from `EventStore` for registered message resolution. Claim removal and batch ordering are server behavior, not emulated by a Go test fake.
