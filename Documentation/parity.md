Chronicle.Go targets the C# client's concepts and behavior, expressed through Go's explicit ownership, contexts and typed registration. This foundation is **not overall client parity or production lifecycle completeness**.

## Baselines and evidence

C# reference: `Cratis/Chronicle` revision `2e31b0dfba489159b3db323238f16d0f277056b4`, paths below relative to `Source/Clients/`. Generated contracts independently pin Chronicle **19.29.4**, commit `ae5e00a8abaa688138b2c2f689e2b4659cccb4fd`. Real-kernel evidence uses **19.29.4-development**, including test-owned TLS/TCP connection interruption and recovery against a running kernel. Whole-kernel restart and a real multi-node deployment remain unverified. SDK release numbers are independent of protocol versions.

Registration, namespace, serialization and concurrency corrections follow **v19.29.4** at the contract commit above: `Source/Clients/DotNET/Events/EventTypes.cs`, `Source/Clients/DotNET/EventStoreNamespaceName.cs`, `Source/Infrastructure/Schemas/{TypeFormats,JsonSchemaExtensions}.cs`, `Source/Infrastructure/Json/ExpandoObjectConverter.cs`, `Source/Kernel/Storage.MongoDB/ExpandoObjectConverter.cs`, and `Source/Kernel/Core/{EventTypes/EventTypeRegistrar,EventSequences/Concurrency/ConcurrencyValidator}.cs` (repository-root paths).

Statuses: **Implemented** means the named behavior has executable regression evidence; **Partial** names an implemented subset; **Not implemented** claims no usable surface; **Go-specific** identifies an intentional translation. The evidence column names test functions or the actual deterministic generation check, not source reading alone.

## Deliberate differences and migration guidance

1. **TLS validates by default.** C#'s local profile skips validation. Add `WithDevelopmentDefaults` only for development; configure real roots/client certificates with `WithTLS` for production. Explicit validating TLS wins over security opt-outs.
2. **Root registration is explicit and snapshotted.** Use `RegisterEvent[T]`, `RegisterReadModel[T]` and `Registry.AddConstraint` before `NewClient`. Model-bound projection tags and typed type-level options preserve attribute-driven declarations alongside the fluent builder; only root admission replaces assembly scanning. No global `init` registry. `WithRegistryForStore` replaces, rather than merges with, the default catalog.
3. **Context replaces ambient state.** Pass `metadata.WithCorrelation`, `WithIdentity` and `WithCausation`; the client does not invent application/program audit facts. Namespace selection remains explicit and does not grant tenant access.
4. **Errors describe write ambiguity.** Domain rejection is a result; operation failures remain errors. Unknown outcomes are never represented as known rejection. `Err` exposes both constraint and concurrency categories; no transparent append retry is added.
5. **Unsupported options fail.** API keys, plaintext and URI certificate/password formats return `ErrUnsupported`, rather than silently skipping security or routing behavior. Use `WithTLS` for PEM material.
6. **Serialization has a deliberately bounded schema contract.** Fundamentals `Concept[T]` and standard codecs replace `ConceptAs<T>`; plain named primitives remain supported. Explicit JSON tags are recommended. Unsupported custom/protected shapes fail registration; no PII/encryption tag can silently send plaintext. Empty exact type IDs and IDs containing commas fail validation. Scalar/array integers use kernel formats; unsigned values above `MaxInt64` fail before dispatch because the 19.29.4 MongoDB append path parses bare JSON integers as signed BSON integers. Use strings for that range. Dictionary integers outside -2^53 through 2^53 fail before dispatch, including nested values, because the kernel converts dictionary numbers through `double`. Use typed struct properties or strings for wider values. Nullable pointer schemas preserve absence; `omitzero` follows Go `IsZero` methods, but omitted non-nullable fields may materialize as kernel defaults.
7. **Protected concurrency cannot silently downgrade.** No-match uses both wire fields. A confirmed commit without the requested check returns its committed result plus `ErrUnsupported`: do not retry. A single append rejects scopes naming another source; `AppendBatch` supports independently labeled checks. Duplicate labels and source/label mismatches fail locally. Batch check flags mean every scope was checked, so mixed checked/unchecked batches may legitimately report false; the wire carries no per-scope success flags.
8. **Resource ownership is explicit.** Constructors are lazy; `Dial` performs preflight. Close cancels/joins owned work but never closes borrowed channels/token sources. `EventSequence` returns a construction error for invalid IDs rather than publishing an invalid handle. Scalar options are last-wins; conflicting auth modes are errors.
9. **Generation validation matches C# defaults.** Registrations include the current schema in `Generations` and default to disabling schema/migration validation, allowing generations above one without migrations. Use `WithEventTypeGenerationValidation(true)` to protect existing generation schemas; generations above one then require migration authoring, which is not implemented. Disabled validation permits overwriting history's schema. Shared C#/Go IDs require compatible generated schemas when validation is enabled; identical payload names alone are insufficient.
10. **The default namespace is `Default`.** This corrects the earlier lowercase `default` value to match C# and the kernel. MongoDB rejects namespaces differing only by case; callers must use the kernel spelling or explicitly select another namespace.
11. **Recovery is supervised, not application replay.** Slice 3 replaces slice 1's explicit-connect-after-loss behavior with automatic generation replacement, following `Connections/ChronicleConnection` and `ConnectionWatchdog` at the reference revision above. Old workers join before replacement. Unlike C#'s broad gRPC retry policy and permissive compatibility fallback, Go fails compatibility/authentication closed and never retries an ambiguous append. Terminal failures require an explicit `Connect`; transient reconnect runs with time-bounded attempts and capped jittered backoff until shutdown.
12. **Registration outcomes describe only implemented stages.** Store-wide definitions share a barrier; namespace readiness stays separate. A batch acknowledgement is not a per-artifact verdict. Transient registration failures receive bounded retries and delayed background retry; deterministic validation/authorization failures require an explicit retry rather than endlessly repeating. Go adds a per-attempt budget and a 64-endpoint discovery/probe bound. Runtime registry extension remains deferred.
13. **Shutdown is context-bounded without breaking `Close()`.** `Shutdown(ctx)` drains admitted RPCs, then cancels and joins; `CloseContext(ctx)` immediately cancels and bounds the join. A timeout reports incomplete cleanup, which continues until cooperative callbacks return. The unchanged `Close() error` remains an unbounded cancellation/join convenience. Borrowed channels retain caller ownership.
14. **Read filters describe kernel history, not exact routes.** Empty/default sentinel dimensions do not narrow. Event types match IDs across generations; normalized history filters sort/deduplicate IDs and use generation one. Raw JSON plus generation metadata replaces automatic CLR deserialization. Read results are ordered and malformed/duplicate positions fail; these finite queries do not imply a multi-query snapshot or revision/redaction protection.
15. **Batch scope enrollment is explicit.** A unique label matching a source replaces that source's default first-entry-route scope. Independent labels need no corresponding event. Like C# `EventsWithConcurrencyScopes`, duplicate labels fail, including identical duplicates. Unlike that C# wrapper's restriction on unresolved independent scopes, Go can explicitly `Resolve` an independent filter before the atomic append. An unchecked empty batch is rejected locally. Eventless protected checks work with 19.29.4; an older kernel's event-required validation becomes `ErrUnsupported`, not a no-op success.
16. **Persisted timestamp precision is kernel-limited.** The Go wire keeps 100 ns precision, but the 19.29.4-development MongoDB kernel returns occurrence/causation dates truncated to milliseconds. `TestKernelOrderedAtomicBatchAndHistory` records this server behavior; `TestReadPreservesEnvelopeMetadataAndGenerations` proves conversion retains all precision actually returned. No client-side reconstruction or extra persistence path is invented.

Batch/read C# references above use revision `2e31b0dfba489159b3db323238f16d0f277056b4`; kernel behavior is exercised against the pinned 19.29.4-development image. The runnable [batch example](../examples/batches/main.go) also uses the public production APIs.

## Append configuration and declaration migration

Register the subject policy once alongside the event schema:

```go
registered, err := chronicle.RegisterEvent[CustomerChanged](registry,
    events.WithSubjectResolver(func(event CustomerChanged) (events.Subject, bool) {
        return events.Subject(event.CustomerID), event.CustomerID != ""
    }))
```

`CustomerChanged` is the application's named event struct; the callback must match
that exact declaration type. An append-level `WithSubject` (or `Entry.Subject`)
wins without invoking the callback. Missing subjects fall back to the source ID.

Add `chronicle.WithCheckFirstAppendIntoAScope(true)` to client construction to
protect first writes across all sequence handles, batches and unit-of-work commits.
It stays off by default, matching C# `ConcurrencyOptions`. Explicit `NoCheck`
remains unchecked. A competing writer after an empty-tail read becomes a known
concurrency rejection rather than an unchecked success.

`WithDefaultConcurrencyStrategy` preserves C#'s extension point without dependency
injection: the callback receives the sequence and default source/route filter.
Return an explicit expectation after a `sequence.Tail(ctx, eventsequences.TailFilter(filter))` read, or return
`Resolve` to have the SDK perform its existing matching-tail read. Explicit
expectations do not trigger an extra read. Batch defaults invoke the strategy once
per source using its first entry's route; units of work defer it to commit, never
staging. No retry or extra kernel round-trip is required by this translation.

Call `sequence.ResolveScope(ctx, filter)` to apply this same policy to selected
concurrency dimensions before staging. Resolve each target independently, then
label the returned scopes for `Stage`/`AppendBatch`. This adds no route defaults.
Resolved scopes never reread their tails at dispatch, even when an empty tail is
unchecked under the default first-append policy; that unchecked result retains
its filter but is distinct from an unresolved `Resolve` expectation.

Operation metadata is available through the new `*WithMetadata` append methods,
not by changing the original public result structs. `Operation().EventTypes()`
retains generations on success, rejection and unknown outcomes; `Result().Target`
still describes only confirmed committed work. Local failures include registered
input types only, because an unregistered value has no persisted identity. Existing
callers can keep their original methods and unkeyed literals unchanged.

## Unit-of-work migration

Transaction references use C# revision `2e31b0dfba489159b3db323238f16d0f277056b4`, `Source/Clients/DotNET/Transactions/{IUnitOfWork,IUnitOfWorkManager,UnitOfWork,UnitOfWorkManager,UnitOfWorkLifecyclePolicy}.cs`. The Arc consumer reference is `Source/DotNET/Chronicle/Commands/TransactionalCommandScope.cs`: completion is distinct from confirmed commitment, and early commitment completes shared work.

1. **Separate participant and owner.** Replace ambient `IUnitOfWorkManager.Begin/Current/SetCurrent/TryGetFor` with `transactions.Begin` and explicit participant context accessors. Go has no `AsyncLocal`; there is no global correlation registry. `UnitOfWork.Stage` translates `AddEvents`. Only the separately retained `Owner` exposes `Commit`/`Rollback`; this capability split also keeps ordinary Arc handlers from completing outer work. The store, namespace, sequence, correlation and actor are fixed at begin. Missing correlation is generated once; actor changes fail because one atomic request cannot represent several actors.
2. **Strict lifecycle and global order.** Go uses C#'s strict-policy intent, not its legacy compatibility mode. All enrollment retains A1/B1/A2 order instead of legacy single-event source grouping. Events serialize at `Stage`, not commit, so later mutations cannot change the transaction. Concurrent stage calls enroll atomically; no serialization callback or RPC runs under the state lock. Repeated equal explicit scopes join, while conflicting scopes fail without mutation. An explicit `Resolve` is not C#'s absent `NotSet`: it includes a filter and cannot overwrite an enrolled expectation. Use omission for the default strategy.
3. **Inspect final disposition, not completion alone.** `Commit` returns the existing Go `BatchResult` and operation error; `Result`, C#-named diagnostic getters, `IsSuccess` and `TryGetLastCommittedEventSequenceNumber` preserve the query workflow. `GetEvents` returns defensive JSON snapshots rather than mutable CLR event objects. Transport loss and errors-only kernel results remain outcome-unknown, not a successful default result or known rejection. All attempts are terminal, including local cancellation; retry requires a deliberate new unit and fresh decision, and is never safe merely because an ambiguous owner completed. The retained result survives a repeated commit error. Empty completion is successful without persistence; scope-only completion still validates through the kernel.
4. **Explicit rollback instead of disposal.** Defer `Owner.Rollback` for pending cleanup. Unlike C#'s repeated rollback exceptions, terminal rollback is a no-op so ordinary Go defer does not mask a successful result; it never changes a committed or ambiguous disposition. During completion it fails with `ErrCompleting`. Rollback reports `RolledBack` and is not `IsSuccess`, avoiding C#'s success-shaped empty append result being mistaken for commitment.
5. **Completion notification retains the C# name and replacement semantics.** `OnCompleted` replaces the callback and runs synchronously after final state, including commit failure and rollback. Go rejects late registration with `ErrCompleted` rather than silently retaining an uncallable callback. No manager-cleanup callback is replaceable, since lifetime belongs to the explicit owner. Callback panic propagates after final disposition is recorded.

The [unit-of-work guide](events/unit-of-work.md) and [executable example](../examples/unitofwork/main.go) show the participant/owner workflow. Prepared batches are a lower-level serialization seam, not another owner: they do not provide once-only completion. Protected model reads and decision tokens remain a separate, unimplemented capability; ordinary concurrency scopes must not be presented as protected-read tokens.

Providers run outside the RPC lease so they can use client lifecycle APIs without self-deadlocking; shutdown does not wait for caller-owned message formatting.

Store-specific registries replace both events and constraints. Adding constraints after client construction requires a new client until runtime extensions exist.

No UUID dependency, new scalar type, local uniqueness algorithm or preflight read is added. Low-level `eventsequences.New` has no registry/message provider and preserves kernel text; obtain sequences from `EventStore` for registered message resolution. Claim removal and batch ordering are server behavior, not emulated by a Go test fake.

Read-model references use the C# baseline revision above, `Source/Clients/DotNET/ReadModels/{IReadModels,ReadModels,ReadModelTypeExtensions,ReadModelJsonSerialization,ReadModelReleaser,ReadModelSubjectResolver}.cs` and `Source/Kernel/Grpc/ReadModels/ReadModels.cs`. 2. **Identity and container names stay distinct.** C# uses `Type.FullName`; Go uses its import-qualified type name, not the simple event-type naming convention. 3. **Presence and progress are separate.** `Instance[T].Exists` replaces a nullable model; `LastHandled` replaces C#'s injected `__lastHandledEventSequenceNumber` property. 4. **Sessions have explicit cleanup contexts.** `NewSession` creates an opaque random ID, binds all coordinates and performs no I/O until Get. `Close(ctx)` dehydrates, reports errors and permits cleanup retry after failure; it is intentionally not `io.Closer`, so callers retain cancellation/deadline ownership. As in kernel `ReadModelsCompliance.HandleBySubject`, top-level properties are grouped by their `__subjects` entry, falling back to the resolved default subject. Each group is released under its own subject and the replies are merged; any group failure returns no document. Typed release uses the same path after serialization and requires the subject on the value. This intentionally adds raw-document lineage handling absent from the typed C# helper. Only explicit scalar-string PII schema metadata is supported here; unsupported classifications still fail registration. Cryptographic/erasure semantics remain kernel-owned, not a client-side cipher heuristic.

The [read-model reference](read-models/index.md), `ExampleRegisterReadModel` and [runnable example](../examples/readmodels/main.go) use these public APIs. Kernel registration, absence, producer-backed materialization and passive reads are tested on 19.29.4-development. Session hydration/dehydration and explicit release failures retain bufconn evidence, not a claim of complete projection/compliance integration.

### Compilation and migration boundaries

- `declarations.Parse(declarations.V1, tag)` is the shared, bounded parser. `FuzzParse`, grammar/error tests and `TestDeclarationsOnIgnoredFieldsFailClosed` cover delimiters, escaped strings, offsets, ignored fields and fail-closed role checks. Unsupported compliance and event-field directives remain errors, not no-ops. Arithmetic, global mappings and nodes use this same parser.
- `serialization.Plan.Fields()` supplies detached field/index, serialized name/path, declared type, nullability and scalar/format metadata. Projection code never invents another casing policy. `TestFieldMetadataSharesPlanAndOwnsSnapshots` covers snapshot isolation. Fundamentals wrapper compatibility is centralized in `scalarCompatible` and `concepts.Underlying`, without calling fabricated concept values. Child parent-key inference retains declared domain-ID types.
- All event references resolve only against the frozen store catalog: bare Go name, `go("qualified.Type")`, `id("persisted-id"[,generation])`, or a typed `BindEvent` alias. Tests cover aliases, exact generations, ambiguity with qualified candidates, foreign handles and store isolation. Runtime validation is mandatory; ordinary gopls rename and Go vet do not validate custom tags. Generation/analysis tooling remains deferred.
- Model-bound precedence is C#'s family order (`set`, `add`, `subtract`, `increment`, `decrement`, `count`, `context`, `value`, `clear`), with last-in-family wins and inspectable shadowing diagnostics. Fluent duplicate writers fail. `TestModelBoundPrecedenceAndFluentDuplicateRejection` fixes this distinction. Mixing mapping tags and fluent mappings fails rather than applying accidental precedence; identity/exclusion tags are shared.
- The one encoder emits the canonical immutable definition. `TestFluentBuildSnapshotsValuesAndCallbacks` and golden mutation tests prove literal/callback/protobuf ownership. Reconnect uses those definitions without reflection or author callbacks. Defaults are `{}`, active, rewindable and AutoMap enabled. The model-bound/explicit projection ID defaults to the model observer ID when set, otherwise the full Go model type name, independently of an overridden read-model identifier; `TestProjectionDiscoveryInheritsModelDefaults` and `TestFluentBuilderInheritsModelDefaults` cover both front ends. Zero `Definition` accessors return zero metadata (`TestZeroDefinitionAccessors`); `WithIdentifier` or a builder ID selects shared C# identities. Container naming remains a read-model setting.
- `NewClient` fails the whole declaration graph before I/O rather than C#'s log-and-skip discovery. Each registry snapshot includes events, models, constraints and projections under one lock. `TestProjectionStartupValidationIsAtomicAndStoreLocal` proves forward references and failure atomicity. Models with mapping tags discover projections; type-level options require `AddProjection`. Explicit foreign model handles and conflicting producer settings fail.
- Registration follows event types and read models, in the observers/constraints portion of the pass. `TestProjectionDiscoveryRegistrationAndFrozenReplay` proves store-wide sharing, producer binding, read barriers, unchanged reconnect definitions and namespace isolation. `TestProjectionFailureCannotPublishReadiness` proves old-kernel rejection. Nonempty projection sets register with `Client` ownership and `FullSet=true`; empty Go sets skip the RPC, so removing all local declarations does not provide a persistent-projection deletion API.
- Kernel `Source/Kernel/Core/Projections/Engine/Expressions/EventValues/{ValueExpressionResolver,LiteralExpressionResolver}.cs` at the revision above restricts literals to BMP letters, combining marks, decimal digits, connector punctuation, space and `._/:*+-`. `TestKernelUnrepresentableModelMappingsFailAtNewClient`, `TestKernelUnrepresentableKeysFailAtNewClient` and `TestFluentLiteralUTF16Boundary` cover UTF-16 limits. Exact event paths `true`, `True`, `false` and `False` fail because the kernel resolves them as boolean literals first; `TestBooleanPropertyPathsRejectLiteralResolverAmbiguity` covers fluent mappings. Quotes, commas, semicolons, parentheses and newlines cannot be escaped into support. The Go compiler rejects them instead of allowing the kernel's partial regex match. Literal error strings are redacted. Schema/range/format validation remains authoritative; no arbitrary `$...` passthrough exists.
- These mappings are not full projection parity. Variants, global handlers, concrete recursive prerequisites, build-local fingerprints, source inference and preview/query are covered below under projections part 3. Initial-state authoring, artifact labels and runtime registration extensions remain unimplemented. Polymorphic/custom-codec schema support is still a dependency, not silently flattened.

The [projection guide](projections/index.md) presents model-bound declarations first and fluent declarations second. `TestProjectionSnippetsMatchCompiledExample` prevents drift from the [executable example](../examples/projections/main.go).

### Shared reducer recovery defect

Go preserves C#'s failed-batch response: last successful observation with no state.
At Chronicle revision `2e31b0dfba489159b3db323238f16d0f277056b4`,
`Source/Kernel/Core/Observation/Reducers/ReducerPipeline.cs:59–75` reloads the
sink state and writes nothing on failure. `Observer.Handling.cs:166–205` advances
observation progress and records a live failure at the last successful event.
`Observer.Failing.cs:223–229` and `Jobs/RetryFailedPartition.cs:89–104` restart
recovery there, inclusively (`Storage.MongoDB/EventSequences/EventSequenceStorage.cs:920–926`).
They do not rebuild from the beginning of the failed batch or event history.
Consequently, successful prefix folds before that restart position are lost.
A failed recovery step additionally checkpoints success and records its next
failed event (`Jobs/HandleEventsForPartition.cs:182–190,236–272`), again without
persisting the prefix. This upstream defect is tracked in
[Chronicle #4540](https://github.com/Cratis/Chronicle/issues/4540); Go does not
change the failure wire contract independently. This conclusion is based on
source inspection, not a live-kernel recovery test.
